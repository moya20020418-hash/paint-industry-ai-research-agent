# Daily Market Research Workflow

**バージョン:** 1.0  
**対象:** 企業・市場・業界調査レポートの自動生成  
**設計方針:** 将来的な Claude Code Dynamic Workflows / サブエージェント実行に対応できるよう、各担当の境界・入力・出力・完了条件を明確に定義する

---

## このワークフローの使い方

### Claude Code への指示例

```
workflows/daily-market-research-workflow.md に従って、
inputs/sample_input.md をもとに市場調査レポートを作成してください。
```

### 対応テーマ

- 防錆・インフラ補修市場
- 常温亜鉛めっき・表面処理・建設補修
- AIエージェント・Claude Code活用・製造業AI導入
- 企業分析・競合調査・市場調査（汎用）

---

## 最重要ルール（全担当共通）

| ルール | 内容 |
|--------|------|
| 三層分離 | 事実・推測・示唆を必ず分ける。混在禁止 |
| 根拠の明記 | 数値・統計には必ず出典を付ける |
| 根拠不明の扱い | 根拠不明の数値は「【根拠不明】」と付記して断定使用禁止 |
| 一次情報優先 | 公式サイト・公式PDF・政府統計を最優先する |
| 断定禁止 | 入力にない事実を断定しない |
| 調査不足 | 情報が不足する場合は「要追加調査」と記載して止める |
| 禁止表現 | 「絶対」「保証」「必ず」「最適」「万能」「問題ありません」「確実に」 |

## Step 0: Web Collector（任意・手動実行）

**担当:** `src/web_collector.py`（Python スクリプト）  
**実行コマンド:** `python src/main.py --collect-web`

### 役割

`config/sources.json` に登録されたURLにアクセスし、HTMLからテキストを抽出して `inputs/web_collected_{YYYYMMDD}.md` に保存する。

### 入力

| 入力 | ファイル | 必須 |
|------|----------|------|
| 情報源リスト | `config/sources.json` | 必須 |

### 実行内容

1. `sources.json` の `sources` 配列を読み込む
2. 各URLに対して以下を実行する：
   - `respect_robots_txt: true` の場合は robots.txt を確認し、禁止URL はスキップ
   - `requests.get()` でHTMLを取得（タイムアウト: `request_timeout_sec` 秒）
   - `script/style/nav/footer/header/aside/noscript/meta/link` タグを除去
   - テキストを最大 `max_text_chars` 文字に制限して保存
   - アクセス間隔 `min_interval_sec` 秒を確保
3. 成功・失敗を問わず全URLの結果を Markdown に記録する

### 出力

| 出力 | ファイル |
|------|----------|
| 収集テキスト | `inputs/web_collected_{YYYYMMDD}.md` |

### 完了条件

- `inputs/web_collected_{YYYYMMDD}.md` が生成されていること
- 収集失敗のURLが「収集失敗」テーブルに記録されていること

### 禁止事項

- 収集テキストをそのまま「事実確認済み」として扱うこと
- `min_interval_sec` を 1 秒未満に変更すること
- `respect_robots_txt` を `false` に変更すること

### 失敗時の対応

- 個別URLの取得失敗はスキップして次のURLに進む（処理を止めない）
- 全URL失敗でもファイルは生成される（失敗テーブルのみのMarkdown）
- ネット非接続環境では Step 0 をスキップして Step 1 から開始すること

## Step 1: Input Loader

**担当エージェント:** `agents/researcher.md`（入力フェーズ）  
**スキル参照:** `skills/market-research-skill.md`

### 役割

`config/topics.json` と `inputs/*.md` を読み込み、後続ステップが使用できる形に整理する。

### 入力

| 入力 | ファイル | 必須 |
|------|----------|------|
| 調査テーマ定義 | `config/topics.json` | 必須 |
| 調査メモ・URL | `inputs/*.md` | 必須（最低1ファイル） |

### 実行内容

1. `topics.json` から対象テーマの `name`・`keywords`・`target_companies` を取得する
2. `inputs/*.md` 全ファイルを読み込む
3. 以下のカテゴリに仕分けする：

```
- 調査テーマ（確定）
- 参考URL（一覧）
- 収集メモ（箇条書き）
- 未解決・要確認事項（- [ ] で書かれたTODO）
- 信頼度メモ（表がある場合）
```

### 出力

```
# Input Summary
## テーマ: {topic_name}
## キーワード: {keywords}
## 対象企業: {companies}
## 参考URL: {urls}
## メモ件数: {count}
## TODO件数: {todos}
```

### 完了条件

- `topics.json` が正常に読み込まれた
- `inputs/` 内に有効な `.md` ファイルが1件以上ある
- テーマ・URL・メモ・TODOの4カテゴリが整理されている

### 禁止事項

- 入力ファイルに存在しない情報を補完しない
- TODOを自動的に「解決済み」にしない
- URLの内容を自動アクセス・解釈しない（MVP フェーズ）

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| `topics.json` が存在しない | 処理停止。「config/topics.json が見つかりません」と報告 |
| `inputs/` が空 | 処理停止。「inputs/ にMarkdownファイルを追加してください」と報告 |
| テーマIDが一致しない | デフォルトテーマを使用し、その旨を出力に明記 |

## Step 2: Researcher

**担当エージェント:** `agents/researcher.md`  
**スキル参照:** `skills/market-research-skill.md`

### 役割

Step 1 の整理済み入力をもとに、市場・業界・企業情報を調査・分類する。

### 入力

| 入力 | 来源 |
|------|------|
| Input Summary | Step 1 の出力 |
| 入力メモ全文 | `inputs/*.md` |

### 実行内容

1. 入力メモを以下の3層に分類する：

```
【事実】  : 公式資料・一次情報で確認できる記述
【推測】  : 事実から論理的に導出できる内容
【要確認】: 根拠不明・未確認の記述
```

2. 市場・業界・企業それぞれについて整理する
3. 情報が不足している領域を「要追加調査」としてリストアップする

### 出力

```markdown
## 事実として確認できること
- 【事実】（内容）（出典：○○）

## 推測
- 【推測】（内容）（根拠：上記事実○）

## 要確認・要追加調査
- 【要確認】（内容）
- 【要追加調査】（不足している情報の説明）
```

### 完了条件

- 全メモが3層いずれかに分類されている
- 「要追加調査」が明記されている
- 未分類の情報が0件

### 禁止事項

- 入力にない事実を新たに追加しない
- 【推測】に「事実」の確認なしで断言表現を使わない
- URLの内容を想像で補完しない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| 全情報が【要確認】のみ | 「入力情報が不十分です。公式資料URLや確認済み情報を inputs/ に追加してください」と報告して停止 |
| 分類不能な記述 | 【要確認】に分類し、理由を付記する |

## Step 3: Source Auditor

**担当エージェント:** `agents/source-auditor.md`  
**スキル参照:** `skills/source-audit-skill.md`

### 役割

Step 2 の情報源を信頼度ランクで評価し、使用可能・要確認・使用禁止を判定する。

### 入力

| 入力 | 来源 |
|------|------|
| 事実・推測・要確認リスト | Step 2 の出力 |
| 参考URLリスト | Step 1 の出力 |

### 実行内容

各情報源に以下のランクを付ける：

| ランク | 定義 | 使用方針 |
|--------|------|----------|
| A | 一次資料（公式サイト・有報・政府統計・公式PDF） | そのまま使用可 |
| B | 二次資料（業界誌・学術論文・信頼性の高い調査会社） | 【B資料】と明記して使用可 |
| C | 三次資料（まとめサイト・ブログ・業界人の個人発信） | 【要確認】として保留 |
| D | 禁止（SNS・掲示板・出所不明） | 除外・使用禁止 |

### 出力

```markdown
## 資料監査結果

| 情報 | 出典 | ランク | 判定 |
|------|------|--------|------|
| （内容） | （URL or 資料名） | A/B/C/D | 合格/保留/除外 |

## 除外した情報
- （除外した内容と理由）
```

### 完了条件

- 全情報源にランクが付いている
- ランクDの情報が全て除外されている
- 除外リストが明記されている

### 禁止事項

- ランクDの情報をレポートに使用しない
- ランクCの情報を「事実」として使用しない
- 出典不明の情報にランクAを付けない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| ランクA情報が0件 | 「公式資料が不足しています。レポートの信頼性が低下します」と警告して続行 |
| 全情報がランクC以下 | 「一次資料が存在しません。調査を停止します。公式URLを inputs/ に追加してください」と報告して停止 |

## Step 4: Numeric Checker

**担当エージェント:** `agents/numeric-checker.md`  
**スキル参照:** `skills/numeric-check-skill.md`

### 役割

監査済み情報から全数値を抽出し、根拠の有無を判定する。

### 入力

| 入力 | 来源 |
|------|------|
| 監査済み情報リスト | Step 3 の出力 |

### 実行内容

1. 以下の種別の数値を全て抽出する：
   - 市場規模（○兆円・○億円）
   - 成長率・伸び率（○%増）
   - 市場シェア（○%）
   - 技術仕様値（亜鉛含有率○%など）
   - 統計数値（件数・棟数・企業数など）
   - 年数・期間（○年以上など）

2. 各数値を3分類する：

| 分類 | 条件 | 表記 |
|------|------|------|
| 根拠あり | ランクA資料で確認済み、出典明記 | （そのまま使用） |
| 要確認 | 出典あるがランクB/C | 【要確認：○○調べ】 |
| 根拠不明 | 出典なし・ランクD | 【根拠不明・使用禁止】 |

### 出力

```markdown
## 数値確認リスト

| 数値 | 内容 | 出典 | ランク | 使用可否 |
|------|------|------|--------|----------|
| 96%以上 | 亜鉛含有率 | ローバル公式サイト | A | 使用可 |
| ○兆円 | 市場規模 | 出所不明 | D | **使用禁止** |
```

### 完了条件

- 全数値にランクと使用可否が付いている
- 「根拠不明・使用禁止」の数値がレポート本文に含まれていない

### 禁止事項

- 根拠不明の数値をレポートに記載しない
- 複数サイトに同じ数値があっても、一次資料未確認なら「根拠不明」とする
- 古い統計（5年超）を年数記載なしで使用しない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| 使用可能な数値が0件 | 「数値根拠なし」の旨を記載してセクション7を空欄で出力 |
| 年数不明の統計 | 「○年時点不明」と付記して【要確認】に分類 |

## Step 5: Competitor Analyst

**担当エージェント:** `agents/company-analyst.md`  
**スキル参照:** `skills/company-analysis-skill.md`

### 役割

入力情報に登場する競合企業・代替技術・周辺市場を整理し、対象企業・製品との差異をまとめる。

### 入力

| 入力 | 来源 |
|------|------|
| 監査済み情報リスト | Step 3 の出力 |
| 調査テーマの target_companies | Step 1 の出力 |

### 実行内容

1. `target_companies` に列挙された企業について情報を整理する
2. 入力メモに登場する競合・代替技術を抽出する
3. 比較軸を設定し、公式資料ベースの事実のみで比較表を作成する

比較軸の例（テーマに応じて変更）：
- 製品の主要特性（亜鉛含有率、耐食性など）
- 適用範囲・禁止素材
- 価格帯（公開情報のみ）
- 市場ポジション（入力情報のみ）

### 出力

```markdown
## 競合・比較整理

### 対象企業一覧
- （企業名）：（公式確認済みの特徴）

### 比較表
| 比較軸 | 対象企業 | 競合A | 競合B |
|--------|---------|-------|-------|
| （軸） | （値・出典） | 【要確認】 | 【要確認】 |

### 情報不足の項目
- （比較できなかった項目と理由）
```

### 完了条件

- target_companies の全企業について記述がある（情報不足の場合は「要追加調査」）
- 比較表の全数値に出典が付いている
- 「情報不足の項目」が明記されている

### 禁止事項

- 公式資料のない競合批判を記載しない
- 「〇〇より優れている」等の主観的評価を使わない
- 未確認情報で比較表の空欄を補完しない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| 競合情報が入力に存在しない | 比較表を省略し「競合情報は inputs/ に追加してください」と記載 |
| 対象企業の公式情報なし | 「【要追加調査】公式資料が未登録」として記載 |

## Step 6: Insight Agent

**担当エージェント:** `agents/insight-agent.md`  
**スキル参照:** `skills/insight-extraction-skill.md`

### 役割

確認済みの事実と推測をもとに、市場・企業・戦略上の示唆を導き出す。

### 入力

| 入力 | 来源 |
|------|------|
| 確認済みの事実リスト | Step 2・3 の出力 |
| 競合整理 | Step 5 の出力 |

### 実行内容

1. 事実 → 推測 → 示唆 の順に論理展開する
2. 各示唆に「根拠となる事実」「前提条件」「確認が必要な事項」を添える
3. 「市場への示唆」「企業への示唆」「調査への示唆（次のアクション）」に分類する
4. **AI活用機会の抽出（中小企業・非エンジニア向け）：**
   - 塗料業界・防錆業界でAIが使える業務領域（問い合わせ対応・製品適合確認・市場調査・提案書作成など）を抽出する
   - 競合がAIをまだ活用していない可能性がある領域をチャンスとして整理する
   - 中小企業（SME）でも実行可能なAI活用案に落とし込む（大規模投資不要・既存ツール活用優先）
   - 非エンジニアでも理解できる言葉で施策化する（「機械学習モデル構築」ではなく「よくある質問への自動返答仕組み」など）
   - 社内で上司・経営者に提案できる具体施策として整理する

示唆の形式：

```
【示唆】（内容）
根拠：（参照した事実・推測のID or 内容）
前提：（この示唆が成立するための条件）
要確認：（示唆を実行する前に確認すべきこと）
```

### 出力

```markdown
## 示唆

### 市場への示唆
- 【示唆】...

### 企業・製品への示唆
- 【示唆】...

### 次の調査アクション
- 【示唆】...
```

### 完了条件

- 全示唆に「根拠」「前提」「要確認」が付いている
- 事実・推測と明確に分離されている
- 断定表現（「必ず」「確実に」等）が使われていない

### 禁止事項

- 入力にない事実から示唆を導かない
- 「〜は確実です」「必ず〜になります」等の断定をしない
- 調査が不足している領域で具体的な推奨をしない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| 確認済み事実が不足して示唆が導けない | 「事実情報が不十分なため示唆の生成を保留します。要追加調査を参照してください」と記載 |

## Step 7: Red Team Critic

**担当エージェント:** （将来追加予定：`agents/red-team-critic.md`）  
**スキル参照:** （将来追加予定）

### 役割

Step 6 までの結論を批判的視点で検証し、弱点・反証・過剰主張・抜け漏れを指摘する。

### 入力

| 入力 | 来源 |
|------|------|
| 全ステップの出力 | Step 1〜6 |

### 実行内容

以下の観点から検証する：

1. **過剰主張チェック:** 「事実」として記述されているが実際には「推測」ではないか
2. **反証チェック:** 別の解釈・逆の事例が存在しないか
3. **抜け漏れチェック:** 調査すべき重要な視点が欠落していないか
4. **バイアスチェック:** 特定の企業・技術に有利な方向に情報が偏っていないか
5. **時制チェック:** 古い情報を現在のこととして記載していないか

### 出力

```markdown
## レッドチームレビュー

### 過剰主張の疑い
- （該当箇所）：（指摘内容）

### 反証・代替解釈
- （指摘）

### 抜け漏れ
- （不足している視点）

### バイアス
- （偏りの指摘）

### 時制の問題
- （古い情報の指摘）

### 総評
（修正が必要な項目数・重要度）
```

### 完了条件

- 5つの観点すべてについてコメントがある（問題なしの場合も「問題なし」と明記）
- 修正が必要な項目が列挙されている

### 禁止事項

- 問題なしの場合に「問題なし」の明記を省略しない
- 批判のための批判（修正提案のない指摘だけ）をしない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| 評価対象の情報が不足 | 「情報不足のためレッドチームレビュー不可。Step 2〜6 を再実行してください」と報告 |

## Step 8: QA Agent

**担当エージェント:** `agents/qa-agent.md`

### 役割

レポート全体のハルシネーション・根拠不足・事実と推測の混同・数値誤用を最終チェックする。

### 入力

| 入力 | 来源 |
|------|------|
| 全ステップの出力 | Step 1〜7 |
| レッドチームレビュー結果 | Step 7 の出力 |

### 実行内容

以下のチェックリストを全項目実行する：

| # | チェック項目 | 合格条件 |
|---|-------------|---------|
| 1 | 事実・推測・示唆の分離 | 三層が明確に区別されている |
| 2 | 数値の根拠 | 全数値に出典がある |
| 3 | 根拠不明の排除 | 根拠不明の数値がレポートに含まれていない |
| 4 | 断定表現の排除 | 「絶対」「保証」等がない |
| 5 | ハルシネーション防止 | 入力にない事実を断定していない |
| 6 | 未確認情報の処理 | 【要確認】タグが付いている |
| 7 | 生成日・調査基準日 | 明記されている |
| 8 | レッドチーム指摘の反映 | Step 7 の修正要求が対応済み |
| 9 | TODOの残存 | 未解決TODOがセクション9に記載されている |
| 10 | 禁止表現 | 禁止リストの表現が使われていない |

### 出力

```markdown
## QAチェック結果

| チェック項目 | 結果 | 備考 |
|-------------|------|------|
| 事実・推測・示唆の分離 | ✓ 合格 / ✗ 要修正 | （備考） |
...

### 総合判定
- ✓ **合格** → Report Writer に渡す
- ✗ **要修正** → 対象ステップに差し戻す（差し戻し先：Step ○）
```

### 完了条件

- 10項目全てに結果が記入されている
- 総合判定が「合格」または「要修正（差し戻し先明記）」のどちらかで終わっている

### 禁止事項

- 問題を発見したまま Report Writer に渡さない
- 「大体OK」「概ね問題なし」等の曖昧な判定をしない
- 差し戻し先のステップ番号を省略しない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| 要修正が3件超 | Report Writer への出力を停止し、「重大な品質問題があります。Step ○〜○ を再実行してください」と報告 |
| 判定不能 | 「QA不能：対象データが不足しています」と報告して停止 |

## Step 9: Report Writer

**担当エージェント:** `src/report_generator.py` + `src/templates.py`  
**スキル参照:** `skills/report-writing-skill.md`

### 役割

QA 合格済みのデータをもとに、`reports/` フォルダに最終レポートを出力する。

### 入力

| 入力 | 来源 | 必須 |
|------|------|------|
| QA合格済みデータ | Step 8 の出力 | 必須 |
| 調査テーマ | Step 1 の出力 | 必須 |
| 生成日時 | システム時刻 | 自動 |

### 実行内容

`python src/main.py` を実行し、以下の構成でレポートを生成する：

```markdown
# Daily Market Research Report
> 生成日時・ツール名・注意書き

## 1. 調査テーマ
## 2. 今日の重要トピック
## 3. 入力情報の要約
## 4. 事実として確認できること
## 5. 推測・仮説
## 6. 市場・企業への示唆
## 7. 数値・根拠の確認
## 8. リスク・不確実性
## 9. 次に調べるべきこと
## 10. QAチェック結果
## 11. 塗料業界におけるAI活用余地（SME向け）
## 12. 中小企業でも実行可能なAI活用案
## 13. 非エンジニア向けの実行ステップ
## 14. 競合との差別化可能性
## 15. 社内で提案できる具体施策
## 16. 次に検証すべきデータ
```

> **注意（セクション11〜16）:** 現在の実装（`src/templates.py`）では、セクション11〜16は手動記入スタブとして生成されます（「ここに記入」プレースホルダー）。
> AI支援による自動生成は Phase 3 で対応予定です。

### 出力

`reports/research_report_{topic_id}_{YYYYMMDD_HHMMSS}.md`

### 完了条件

- ファイルが `reports/` フォルダに生成されている
- ファイル名に日付・時刻が含まれている
- セクション1〜16が全て存在する
- QAチェック結果（セクション10）に合格の記録がある

### 禁止事項

- QA 未合格のデータでレポートを生成しない
- セクションを省略しない
- 生成日時を省略しない

### 失敗時の対応

| エラー | 対応 |
|--------|------|
| `reports/` フォルダが存在しない | 自動作成して続行 |
| 書き込み権限エラー | 「レポートを保存できません。フォルダの権限を確認してください」と報告 |
| QA が「要修正」のまま渡された場合 | 処理を拒否し「QA合格後に再実行してください」と報告 |

## ワークフロー実行チェックリスト

レポートを共有・提出する前に以下を確認する：

```
[ ] Step 1: topics.json と inputs/ が読み込まれた
[ ] Step 2: 事実・推測・要確認が分類された
[ ] Step 3: 全情報源にランクが付いた（ランクD除外済み）
[ ] Step 4: 全数値の根拠が確認された（根拠不明は除外済み）
[ ] Step 5: 競合・比較情報が整理された
[ ] Step 6: 示唆に根拠・前提・要確認が付いた
[ ] Step 7: レッドチームレビューが実施された
[ ] Step 8: QAチェック全10項目が「合格」
[ ] Step 9: reports/ にレポートが生成された
```

## Dynamic Workflows 対応メモ

将来的に Claude Code の Dynamic Workflows やサブエージェントで自動化する際の設計指針：

```yaml
# 想定 workflow.yaml 構造（将来実装）
name: daily-market-research
version: "1.0"
steps:
  - id: input_loader
    agent: researcher
    skill: market-research-skill
    inputs: [topics.json, inputs/*.md]
    outputs: [input_summary]

  - id: researcher
    agent: researcher
    skill: market-research-skill
    inputs: [input_summary]
    outputs: [fact_list, todo_list]

  - id: source_auditor
    agent: source-auditor
    skill: source-audit-skill
    inputs: [fact_list]
    outputs: [audited_list]
    parallel_with: numeric_checker

  - id: numeric_checker
    agent: numeric-checker
    skill: numeric-check-skill
    inputs: [audited_list]
    outputs: [numeric_list]

  - id: competitor_analyst
    agent: company-analyst
    skill: company-analysis-skill
    inputs: [audited_list, numeric_list]
    outputs: [competitor_summary]

  - id: insight_agent
    agent: insight-agent
    skill: insight-extraction-skill
    inputs: [audited_list, competitor_summary]
    outputs: [insight_list]

  - id: red_team_critic
    agent: red-team-critic
    inputs: [all_previous_outputs]
    outputs: [critique_report]

  - id: qa_agent
    agent: qa-agent
    inputs: [all_previous_outputs, critique_report]
    outputs: [qa_result]
    gate: all_checks_passed

  - id: report_writer
    script: python src/main.py
    inputs: [qa_result]
    outputs: [reports/research_report_*.md]
```

**並列実行可能なステップ:** Step 3（Source Auditor）と Step 4（Numeric Checker）は並列実行可能。  
**ゲート（停止条件）:** Step 8（QA Agent）が「要修正」の場合、Step 9 に進まない。
